# 多对多表单引用的最终权限接入

按已确认设计继续实施，复用执行计划、测试先行和独立审查流程。本批处理普通根 `update` 中恰好一个 BelongsToMany 字段，输入为有界主键数组，空数组表示解除全部连接。使用现有来源 update 最终 ACL、字段权限、角色条件和 G；只对实际新建连接的目标应用独立中性 list 最终权限、主键读取权限、角色条件及 G/V。

- [x] 真实 ACL/Resourcer/Repository 失败测试：整组替换、增加、移除、原关联保留、历史认领、权限/字段/角色边界、拒绝复杂输入及元数据失效回滚；底层连接事务回归覆盖并发撤权、写偏差和通知行为。
- [x] 将单值入口推广为内部 `AccessReferenceMutationHandler`，共享权限与输入捕获；原单值行为继续由原服务处理，多对多使用原连接事务服务，不复制第二套授权逻辑。
- [x] 在连接事务锁定来源和旧连接后计算差异；新入口只授权新增目标，旧底层调用者的显式目标条件仍保持原行为。中间表仅限纯连接表，独立访问配置、业务字段、跨库、自关联等不支持形态明确拒绝。
- [x] 对来源/目标/中间表身份、元数据、准备阶段和角色条件依赖做贯穿异步与最终查询的检查。新增连接和可选历史来源认领在同一 PostgreSQL SERIALIZABLE 事务中，目标数据不修改。
- [x] SQLite/PostgreSQL 新旧引用入口与连接事务回归：157 通过、33 跳过；严格 TypeScript 诊断 0，聚焦 lint 无警告/错误，格式检查及租户模块构建通过。独立审查无待修正问题。
