# 普通读取的关联路径规划

目标：从普通 `list/get/count` 的原始查询参数识别实际使用的关联路径，供异步关联权限准备器使用；不再要求可信入口手工列出每条筛选、排序或展开路径。

实现位于 `access-control/read-paths.ts`。复用资源参数、字段选择、请求筛选和排序解析器，只在规划阶段为解析器提供内部元数据视图，收集其实际访问的路径；这些视图不是权限，不输出到调用者，也不能执行查询。普通读取仍通过既有最终 ACL、字段、角色和 G/V 校验。多对多关联额外加入真实中间表路径，全部路径去重并限制为 100 条。先固定参数、身份及日期上下文，再调用元数据解析器；不扫描未使用的关系，不为角色内部授权事实补用户读取授权。排序复用已准备配置的同步规划部分，不执行其异步查询。

- [x] 先写失败测试：根读取无关联、嵌套筛选/展开、排序、去重、中间表、日期、非法参数及无 SQL。
- [x] 实现路径收集；严格复用已有参数语义，不另写一套筛选或角色判断。
- [x] 用实际核心权限串联路径规划、异步授权和普通读取，确认缺少目标授权仍拒绝，角色及 G/V 不变。
- [x] 双库聚焦回归、严格类型、lint、格式和租户包构建，独立审查无阻塞问题。

验证：双库关联准备与读取回归 736 项通过；最终读取处理器双库聚焦回归 176 项通过；字段选择、筛选和排序解析器 74 项通过。严格 TypeScript、聚焦 lint、格式及租户包构建通过。补充根表身份回调修改筛选的快照用例后，路径规划 35 项通过。两个独立 PostgreSQL 测试库均已清理。输入格式测试还确认非法数组原型不会被复制过程标准化后绕过原解析器校验。

本阶段仍是内部入口能力，不注册现有业务接口，不启用新模型，不改核心或依赖。
