# 独立多对多连接动作

按已确认设计，使用计划执行、测试先行及独立审查。本批增加内部入口，不安装业务路由或变更核心依赖。

- [x] 真实 ACL/Resourcer/Repository 失败测试：独立 `add/remove/set` 的具体来源、目标本次动作最终决策、来源同名操作中性最终决策及关联字段范围、新增目标独立中性 list 决策。输入在异步前固定，原始路径和动作一致。
- [x] `reference-mutation-handler.ts` 共享表单执行部分，增加 `handleAssociation`。来源字段及角色条件与 G 相交；目标本次动作条件约束全部实际变化目标，新增目标再满足 list 和 G/V；移除或不变旧引用不要求额外 list。来源上下文不得带请求筛选/定位，不制造 ACL 决策。
- [x] `many-to-many.ts` 算出实际差异后调用可选可信整组目标检查，保留旧调用者行为。复用 SERIALIZABLE、Repository、历史认领及写保护；失败完整回滚，只返回来源键和影响数。
- [x] 覆盖来源/目标权限绑定错误、角色及字段限制、仅可见来源、隐藏新增/旧目标、历史认领、异步身份/配置失效。`filterByTk/filterByTks/values` 仅提供一个主键或有界稠密数组，空数组仅 `set` 支持；拒绝目标对象、业务中间表、`_` 来源及其他动作。
- [x] 新旧入口及连接服务 SQLite/PostgreSQL 回归、严格类型、lint、格式、租户模块构建；独立审查，清理随机测试库。

角色字段、白名单和黑名单分别按来源和目标解析，目标动作的字段限制只用于引用定位键，不允许更新目标内容。未适配的最终参数拒绝执行。HasMany、混合字段、业务中间表及生产启用不属于本批。

来源同名根操作是内部契约，不能自行将 add/remove/set 改成 update；正式接入时须结合现有角色和完整 ACL 链验证。来源决策允许核心自动初始化的 `filterByTk: undefined`，但拒绝实际定位值及请求筛选。目标选择只接受上述查询或请求体参数，不接受额外 REST 目标定位段。

独立审查发现的批量边界已按失败/通过验证：600 个旧目标替换为 600 个新目标时，实际变化并集可超过请求数组的 1000 个键上限；逐个归一化持久化主键并按集合核验，避免误拒绝及平方级比较。未扩大原连接服务单次写入的既有限制。空来源定位参数的兼容也已通过失败/修复验证；随机测试数据库由验证脚本自动清理。

验证结果：三个入口/连接服务测试文件共 228 项通过、50 项跳过；补齐空定位兼容后，最终入口测试 129 项通过、35 项跳过。SQLite 不代替 PostgreSQL 事务验证，成功写入用例只在 PostgreSQL 运行。严格 TypeScript、oxlint、Prettier 及租户模块构建全部通过；独立审查复核无未解决问题。
