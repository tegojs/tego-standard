# 单值关联引用的最终权限接入

沿用已确认设计，按 executing-plans 和 test-driven-development 实施。先接普通根 `update` 中只含一个 BelongsTo 字段的引用更换/解除；输入为目标主键或 null。来源实际 update 权限和字段权限、来源角色条件与 G 必须同时通过。新目标另走现有服务端授权链的中性 list 决策，满足其角色条件与 G/V；不要求目标可写，不修改或认领目标。

- [x] 用真实 ACL、Resourcer、Repository 编写并运行失败测试，覆盖字段权限、独立目标授权、G/V、历史记录、非法输入和事务回滚。
- [x] 增加内部 `AccessBelongsToMutationHandler`，复用已有引用事务服务，不注册路由；拒绝嵌套编辑、混合标量更新、直接外键、批量请求、输出展开和底层参数。
- [x] 对元数据、身份映射、准备阶段和角色条件依赖增加贯穿异步调用的检查；特别验证写入后最终查询期间发生变化会回滚。
- [x] 运行引用/普通写入回归、严格类型、lint、格式、模块构建；独立审查后签名原子提交，更新设计进度。

只使用随机独立 PostgreSQL 测试库；关联写事务继续要求 PostgreSQL SERIALIZABLE。SQLite 验证输入拒绝及不支持该事务时明确失败。已有标量新增、更新和删除入口不改变。多值关联、关联目标编辑、批量和混合更新继续留给后续批次；业务数据和生产环境不变。

来源锁定后比较原外键：解除或原值不变不重新授权旧目标；真正更换目标时才调用可信服务端授权回调。目标必须有独立、同角色、中性 list 最终决策且主键可读。旧底层服务调用者显式传入的目标条件保留原有检查，不受新入口的原值处理影响。

验证证据：首轮缺少入口时 6 项失败，包含 PostgreSQL 正常引用和 SQLite 明确不支持的错误码；实现后完整引用及普通更新/删除回归共 221 项通过、17 项仅 PostgreSQL 执行的用例在 SQLite 跳过。移除最终查询后的生命周期检查时，单独回归捕获请求错误成功；恢复后确认回滚、原响应不变。严格 TypeScript、lint、格式和租户模块构建通过。独立静态审查无待修问题。随机测试库已删除。
