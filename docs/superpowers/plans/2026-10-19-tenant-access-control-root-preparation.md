# 普通读取入口的自动关联权限准备

目标：在既有 `AccessRootReadHandler` 增加 `handleWithRelatedContexts`，将自动路径识别、异步最终权限准备和读取串成一次操作。调用者仍负责先完成根资源 ACL，并提供已经完成既有授权链的目标列表上下文；这里不生成模拟请求、不重新计算 ACL、不安装业务中间件。

实现边界：先捕获根动作、原始参数、最终根权限、可信身份及日期，再进入任何异步回调。准备后的关联权限只绑定本次操作；等待期间外部对象变化不能替换原始请求。根权限拒绝时不调用目标授权，目标缺权、准备失败或生命周期变化时不查询或更新响应。已有同步 `handle` 保持行为。

- [x] 在 `reads.test.ts` 增加失败用例：普通列表/详情/计数自动准备，路径去重，无关请求不授权，等待期间输入变化，拒绝/失败和元数据/阶段失效。
- [x] 把根上下文捕获提取到 `root-read-context.ts`，避免处理器与异步准备器的运行时循环依赖；新增方法复用 `collectRelatedReadPaths`、`prepareRelatedReadContexts` 和原有执行器。
- [x] 聚焦测试、双库读取回归、严格类型、lint、格式及租户包构建；独立审查未发现阻塞问题。

仍不改核心或依赖，不启用新模型，不修改本地业务配置或生产数据。现有核心缺少模型范围委托扩展点，真实业务入口激活另行处理。

已验证的边界还包括：等待期间修改日期、身份、根动作或权限对象不改变原查询；传入事务可以读取事务内新记录；并发请求各用自己的关联权限。发现并修复了配置阶段被替换后仍使用旧授权，以及复制过程规范化非法数组原型的两个问题。根参数现在先经原有解析器校验再复制，避免自动组装绕过参数契约。

验证结果：SQLite 与独立 PostgreSQL 测试库的 `reads`、`related-read-contexts`、`final-read-permission`、`resource-read-routing` 四文件共 782 项通过；严格 TypeScript 诊断为 0，修改代码的 oxlint、Prettier 检查及 `pnpm exec tegod build @tachybase/module-tenant` 通过。PostgreSQL 临时测试库已清理，没有修改业务数据库。
