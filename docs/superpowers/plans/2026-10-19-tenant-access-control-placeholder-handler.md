# 关联占位路径的最终权限组装

## 目标和范围

为新租户模型补齐内部 `handlePlaceholderWithRelatedContexts`，处理 `来源表/_/关联字段:get|list`。核心把这种请求交给目标表仓库，允许选择尚未与来源记录关联的目标；`_` 不是真实记录 ID。

沿用已有统一读取服务，不注册路由、不修改核心依赖或业务配置。带具体来源 ID 的关联入口需要另外组装来源、目标和中间表权限，不在此处放行。

## 实施步骤

1. 核对核心 `Resourcer` 的路径元数据和 ACL 中间件：最终权限绑定实际目标集合，而非关联字段名或原始资源路径。
2. 先写真实数据库和核心 ACL 测试，确认缺少处理方法时失败。
3. 捕获动作、最终权限、原始参数、身份和日期，再解析集合身份；核实授权目标与真实关系目标一致。只移除已核对的传输元数据，其他参数继续严格校验。
4. 将目标作为统一读取根，复用字段、筛选、分页、G/V、事务和异步关联授权。具体来源及元数据冲突明确拒绝。
5. 保留原始来源—目标关系的生命周期检查，在异步授权前后、执行前后复核；失败不替换响应。
6. 运行 SQLite/PostgreSQL 回归、严格类型检查、lint、格式和模块构建；独立审查后签名原子提交。

## 验收重点

- 关联名不同于目标集合名，仍使用实际目标的 get/list 权限；没有来源表权限也能按核心占位协议读取目标。
- 未关联目标、归属性可读目标和可见性可读目标正常返回；隐藏目标仍为空。
- 最终角色字段和数据范围与 G/V 相交；嵌套目标独立授权。
- 输入和身份不受后续元数据或异步回调修改影响，事务可读取未提交目标。
- 来源或 REST 元数据冲突、错误角色、错误目标、无权限和不支持选项在 SQL 前拒绝。
- 关系在授权中或执行中替换时整体失败，不发布结果。
