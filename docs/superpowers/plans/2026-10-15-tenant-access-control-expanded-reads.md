# 列表与详情的单层关联组装

沿用已批准设计，使用计划执行、测试驱动和独立审查，在 `feat/tenant-access-control` 完成本阶段。

## 设计

新增内部 `listExpanded` / `getExpanded`，请求包含根读取参数及最多 20 个 `{ association, attributes }` 展开项，只支持单层已登记关系。列表先按根筛选、排序和分页读取，再按整页主键分别批量展开四类关系，不为每条记录补查。详情保留不可读或不存在时返回 `null` 的契约。

根读取增加内部配对页，主键随实际读取取得，仅用于拼接，不扩大根输出字段权限；仅请求关联时可选择空根字段。普通 list/get 的字段及返回契约保持不变。所有关联、目标字段和多对多中间表权限在首个 await 前固定，根筛选排序复用同次权限快照。提前记录全部关系、配置和实际依赖元数据，任一步变化都拒绝返回整份结果。

组装复用三类展开服务；来源和目标及中间表分别满足 G/V 与角色范围，隐藏目标返回 `null` 或空数组，不删除可读根记录。输出不带内部主键、外键、连接内容或 getter；保留原生字段值和大 JSON。事务贯穿根读取与全部展开。

## 验证记录

首个组装测试先因 `listExpanded` 缺失失败。独立审查发现根请求提前复制会规范化特殊数组原型，三个回归用例确认修前意外放行；修复复用根计划的原始校验与同步快照，复审无遗留问题。

最终版本组装测试在 SQLite/PostgreSQL 共 76 项通过；既有根读取及三类展开回归共 536 项通过。覆盖四类关系、字段隐藏、角色与租户范围、共享无租户列、历史数据只读、排序分页、事务、查询阶段结束、并发身份、元数据变化和输入校验；20/100 条根记录查询次数一致。严格 TypeScript 0 诊断，oxlint、Prettier、模块构建和暂存差异检查通过，随机专用 PostgreSQL 测试库已删除并确认清理。
